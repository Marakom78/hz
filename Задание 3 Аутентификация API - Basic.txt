Реализовать аутентификацию и авторизацию пользователей в Api. Разграничить их возможности. Неавторизированнй пользователь может просматривать выдачу конечной точки (методом Get), авторизованный может использовать также остальные методы - POST, DELETE и др. 

Рассмотрим базовую (Basic) аутентификацию для разработанного Api.
Материал для изучения - найти самостоятельно.

1. Реализовать авторизацию на стороне сервера.

В этой части делаем общую часть аутентификации для всех конечных точек Api
1.1 Сделать метод getUserByAuthBasic(): ?User в классе UsersAuthService, который вернет пользователя, указанного в HTTP заголовке Authorization.
1) В этом методе получим логин и пароль пользователя из заголовка Authorization
2) Найдем пользователя в базе данных.
3) Проверим пароль этого пользователя.
4) Вернем пользователя или null, если что-то пошло не так. 


1.2 Изменить Api добавления статьи так, чтобы при запросе на адрес /api/articles методом POST проверялась авторизация пользователя.
1) Создаем базовый контроллер для Api - ApiController.
2) При получении запроса в конструкторе базового контроллера ApiController вызываем метод getUserByAuthBasic() модели UsersAuthService и получаем пользователя в переменную(поле) user.
3) В действии add контроллера ArticlesApiController проверяем пользователя, если это null - выбрасываем исключение UnauthorizedException()
4) При обработке исключения задать заголовок HTTP WWW-Authenticate: Basic и вернуть код 401.

1.3 Изменить Api удаления статьи так, чтобы при запросе на адрес /api/articles/1 методом DELETE проверялась авторизация пользователя и его авторство.
1) Авторизацию пользователя проверяем по аналогии с предыдущим пунктом.
2) В действии delete контроллера ArticlesApiController проверяем, что пользователь является автором статьи, если это не так - выбрасываем ислючение ForbiddenException()
3) При обработке исключения вернуть код 403.

1.4 Изменить Api редактирования статьи так, чтобы при запросе на адрес /api/articles/1 методом PATСH или PUT проверялась авторизация пользователя и его авторство по аналогии с предыдущим пунктом.

1.5 Проверить все Api через Postman.

1.6 Проверить со стороны клиента. Добавить в fetch данные авторизации при добавлении статьи:

1.7 Класс UsersApiController - получение пользователя и логин. 
Этот класс будет управлять сессией пользователя.
1) Сделать класс UsersApiController и в нем действие user.
Действие user отправляет браузеру Json с именем пользователя.
2) В действии user вызвать метод getUserByBasic(), получить пользователя. 
3) Ответ отправить пользователю в виде JSON такого вида {
		"user" : 'login' 
	}
	если пользователь не найден ответ такой:
	{
		"user" : "No authenticated"
	}
4) В классе UsersApiController сделать действие login.
5) Добавить роут по адресу /api/user/login.
6) В действии login по аналогии с приложением (не api) вызываем метод login() модели User. И возвращаем JSON с результатом.
  	Если пользователь успешно вошел - отправить пользователю в виде JSON такого вида 
  	{
		"user" : 'login' 
	}
	если пользователь не найден или пероль не совпадает:
	{
		"user" : "No authenticated",
		"error" : "текст ошибки"
	}

2. Реализовать авторизацию на стороне клиента.

2.1 На странице basic_auth.html реализовать возможность аутентификации пользователя.
При заходе на страницу пользователь не авторизован. Показывается кнопка "Войти", по нажатии которой появляется форма входа.
При отправке формы - перезагрузки страницы не происходит, форма отправляется Fetch - запросом на адрес /api/user/login.
При успешной авторизации выводится имя пользователя и кнопка "Выход", форма входа скрывается.
Если авторизация не удалась - выводится сообщение об ошибке с текстом ошибки, форма остается.

2) Авторизованному пользователю доступно удаление и редактирование своих статей, а также создание новых
